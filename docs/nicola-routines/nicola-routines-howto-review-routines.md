# How to Review and Update Routines

> [!NOTE]
> For routine review rules and schedules, see {{ link_with_abstract("nicola-routines-architecture.md") }}. For core principles, see {{ link_with_abstract("nicola-routines-principles.md") }}.

## 📘 Purpose & Scope

This guide provides step-by-step instructions for reviewing and updating routines in Nicola's routines system. Regular reviews ensure routines remain effective, aligned with goals, and optimized for current context.

## Prerequisites

- Understanding of routine system (see {{ link_with_abstract("nicola-routines.md") }})
- Understanding of core principles (see {{ link_with_abstract("nicola-routines-principles.md") }})
- Access to routine execution data and history

## Review Schedule

### Weekly Review

**Frequency**: Every Sunday  
**Scope**: Daily and weekly routines  
**Duration**: 30-60 minutes

**Review Items**:
- Daily routines effectiveness
- Weekly routines completion
- Routine execution frequency
- Outcome achievement

### Monthly Review

**Frequency**: First of each month  
**Scope**: Monthly routines and overall system  
**Duration**: 60-90 minutes

**Review Items**:
- Monthly routines effectiveness
- System-wide patterns
- Routine dependencies
- Persona activation patterns

### Quarterly Review

**Frequency**: Every 3 months  
**Scope**: Yearly routines and system architecture  
**Duration**: 90-120 minutes

**Review Items**:
- Yearly routines effectiveness
- System architecture evaluation
- Core principles alignment
- Major system changes

## Step 1: Gather Routine Data

**Action**: Collect data about routine execution.

**Data Sources**:
- Routine execution logs
- Completion rates
- Time spent on routines
- Outcome achievement records
- User feedback

**Data to Collect**:
- **Execution Frequency**: How often routine executes
- **Completion Rate**: Percentage of successful completions
- **Time Spent**: Actual time vs. estimated time
- **Outcome Achievement**: Whether outcomes are achieved
- **User Satisfaction**: Feedback on routine effectiveness

**Example**:
- Routine: Morning Routine (R019)
- Execution Frequency: Daily (as expected)
- Completion Rate: 85% (target: 90%)
- Time Spent: 45 minutes (estimated: 30 minutes)
- Outcome Achievement: 80% (target: 90%)
- User Satisfaction: Good

**Verification**: You have routine execution data.

## Step 2: Evaluate Routine Effectiveness

**Action**: Assess if routine achieves its intended outcomes.

**Evaluation Criteria**:
- **Outcome Achievement**: Does routine achieve defined outcomes?
- **Efficiency**: Is routine efficient (time vs. value)?
- **Consistency**: Is routine executed consistently?
- **Relevance**: Is routine still relevant to current context?
- **User Satisfaction**: Is routine satisfying to execute?

**Evaluation Process**:
1. Review routine outcomes
2. Compare actual results to expected outcomes
3. Assess efficiency and time spent
4. Evaluate consistency and execution frequency
5. Consider user feedback and satisfaction

**Example**:
- Routine: Meeting Preparation (R003)
- Outcome: Arrive at meeting with agenda and context
- Achievement: 90% (meetings well-prepared)
- Efficiency: Good (15 minutes, high value)
- Consistency: High (executes before every meeting)
- Relevance: High (still needed)
- Satisfaction: Good

**Verification**: Routine effectiveness is evaluated.

## Step 3: Analyze Routine Usage

**Action**: Analyze how routine is used and when it executes.

**Usage Analysis**:
- **Execution Patterns**: When does routine execute?
- **Trigger Frequency**: How often do entry points trigger?
- **Persona Activation**: Which personas activate routine?
- **Context Patterns**: What contexts trigger routine?
- **Dependency Usage**: How are dependencies used?

**Analysis Process**:
1. Review execution logs
2. Identify patterns in execution
3. Analyze trigger frequency
4. Review persona activation patterns
5. Assess dependency relationships

**Example**:
- Routine: Task Review (R013)
- Execution Patterns: Executes 5-10 times per day
- Trigger Frequency: High (many task notifications)
- Persona Activation: PM (primary), CEO (high priority)
- Context Patterns: Work hours, project work
- Dependencies: None (independent)

**Verification**: Routine usage is analyzed.

## Step 4: Identify Improvements

**Action**: Identify opportunities to improve routines.

**Improvement Areas**:
- **Efficiency**: Reduce time or improve value
- **Effectiveness**: Improve outcome achievement
- **Consistency**: Increase execution frequency
- **Relevance**: Update for current context
- **Satisfaction**: Improve user experience

**Improvement Process**:
1. Review evaluation results
2. Identify specific improvement areas
3. Brainstorm improvement ideas
4. Prioritize improvements
5. Plan implementation

**Example**:
- Routine: Morning Routine (R019)
- Issue: Takes 45 minutes (estimated 30)
- Improvement: Streamline steps, remove unnecessary actions
- Priority: High (affects daily schedule)
- Implementation: Update routine steps, reduce time to 30 minutes

**Verification**: Improvements are identified.

## Step 5: Assess Dependencies

**Action**: Evaluate routine dependencies.

**Dependency Assessment**:
- **Dependency Validity**: Are dependencies still valid?
- **Dependency Order**: Is dependency order correct?
- **Dependency Efficiency**: Are dependencies efficient?
- **Dependency Conflicts**: Are there dependency conflicts?

**Assessment Process**:
1. Review routine dependencies
2. Verify dependencies are still needed
3. Check dependency order
4. Assess dependency efficiency
5. Identify conflicts

**Example**:
- Routine: Weekly Review (R007)
- Dependencies: R001-R006 (daily routines)
- Validity: Still valid (need daily routines first)
- Order: Correct (daily before weekly)
- Efficiency: Good (dependencies complete quickly)
- Conflicts: None

**Verification**: Dependencies are assessed.

## Step 6: Review Routine Priority

**Action**: Evaluate if routine priority is appropriate.

**Priority Assessment**:
- **Current Priority**: What is current priority?
- **Priority Justification**: Why is this priority appropriate?
- **Priority Changes**: Has context changed priority needs?
- **Priority Conflicts**: Are there priority conflicts?

**Assessment Process**:
1. Review routine priority
2. Assess priority justification
3. Consider context changes
4. Evaluate priority conflicts
5. Determine if priority should change

**Example**:
- Routine: Strategic Review (R004)
- Current Priority: High
- Justification: Critical for strategic decisions
- Context Changes: None
- Conflicts: None
- Decision: Keep High priority

**Verification**: Routine priority is reviewed.

## Step 7: Update Routine Definition

**Action**: Update routine definition based on review findings.

**Update Process**:
1. Review improvement recommendations
2. Update routine steps if needed
3. Update metadata if needed
4. Update dependencies if needed
5. Update outcomes if needed
6. Document changes

**Update Guidelines**:
- Make changes incrementally
- Test changes before full implementation
- Document rationale for changes
- Update all related documentation
- Communicate changes if significant

**Example**:
- Routine: Morning Routine (R019)
- Change: Streamline steps to reduce time
- Update: Remove 2 unnecessary steps
- Metadata: Update estimated time to 30 minutes
- Documentation: Update routine reference

**Verification**: Routine definition is updated.

## Step 8: Update Entry Points

**Action**: Update entry points if routine changes affect them.

**Update Process**:
1. Review entry point assignments
2. Check if entry points need updates
3. Update entry point configuration if needed
4. Update entry point catalog
5. Test entry point changes

**Example**:
- Routine: Morning Routine (R019)
- Entry Point: T001 (Morning Routine Trigger)
- Change: None needed (entry point still appropriate)
- Update: None

**Verification**: Entry points are updated if needed.

## Step 9: Update Documentation

**Action**: Update all relevant documentation.

**Documentation Updates**:
- Update routine reference document
- Update entry point catalog if needed
- Update persona definitions if needed
- Update cross-references
- Document change rationale

**Update Process**:
1. Identify all documentation that needs updates
2. Update routine reference document
3. Update entry point catalog if needed
4. Update persona definitions if needed
5. Update cross-references
6. Document change history

**Verification**: Documentation is updated.

## Step 10: Test Updated Routine

**Action**: Test routine after updates.

**Testing Process**:
1. Execute routine with updated definition
2. Verify routine executes correctly
3. Check outcome achievement
4. Verify time estimates
5. Test dependencies
6. Check for errors

**Testing Checklist**:
- [ ] Routine executes successfully
- [ ] Steps are clear and actionable
- [ ] Outcomes are achieved
- [ ] Time estimates are accurate
- [ ] Dependencies work correctly
- [ ] No errors occur

**Verification**: Updated routine works correctly.

## Step 11: Monitor Changes

**Action**: Monitor routine after updates.

**Monitoring Process**:
1. Track routine execution
2. Monitor outcome achievement
3. Collect user feedback
4. Assess improvement effectiveness
5. Adjust if needed

**Monitoring Duration**:
- Short-term: 1-2 weeks
- Medium-term: 1 month
- Long-term: 3 months

**Verification**: Changes are monitored.

## Troubleshooting

### Routine Not Effective

**Problem**: Routine doesn't achieve outcomes.

**Solutions**:
- Review routine steps
- Adjust step sequence
- Add missing steps
- Refine outcome definitions
- Consider routine removal if not needed

### Routine Not Executing

**Problem**: Routine doesn't execute as expected.

**Solutions**:
- Check entry point configuration
- Verify persona activation
- Check routine status
- Review dependencies
- Test entry point triggers

### Routine Takes Too Long

**Problem**: Routine takes longer than estimated.

**Solutions**:
- Streamline routine steps
- Remove unnecessary actions
- Optimize step sequence
- Update time estimates
- Consider breaking into smaller routines

### Dependencies Not Working

**Problem**: Routine dependencies cause issues.

**Solutions**:
- Review dependency definitions
- Check dependency order
- Verify dependencies are available
- Consider making dependencies optional
- Update dependency relationships
