## Palantir (Foundry Fastlane) — Why taxonomies/ontologies matter (with key timestamp links)

Video: https://www.youtube.com/watch?v=Tj0YAbm41vM

### 1) Core idea: business is **objects + relationships**, not datasets
Palantir’s framing is that organizations aren’t understood through tables, extracts, and reports; they’re understood through **real-world business objects** (e.g., aircraft, flights, routes) and the **relationships** between them. Foundry’s Ontology acts as a **semantic layer / shared language** that turns siloed data into connected, decision-ready objects—foundation for analytics, automation, modeling, agents, and day-to-day operations.

### 7) Links and “pivot”: traversing relationships (not Excel pivot tables)
A key learning is **pivoting**: switching context from one object set to another via a relationship (e.g., routes → origin airports). They stress this is graph traversal, not spreadsheet pivoting.
